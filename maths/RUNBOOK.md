# SRJ EDU daily MATHS reel runbook (1 a day, 9 PM IST)

Suraj (2026-11-28, final): **one** new code-made maths reel every day, posted at **21:00 IST** on
Instagram, Facebook and YouTube through Buffer (one reel a day to save credits). Style follows his reference video: black background with a faint moving grid, glowing
white equations, bright colour-coded shapes, camera zooms, green progress bar, `@srj_edu_app` at the top.
English on-screen text. All sound is generated by code (`maths/sound.py`), no samples, no copyrighted music.
This is separate from the science "This vs That" reels in the root `RUNBOOK.md` (do not touch those).

A scheduled task runs this once a day at about 7:17 PM IST. It must finish and schedule the posts before 21:00. Keep it cheap: no extra
render passes, preview only the frames listed in step 5, render each reel once.

## 1. Setup
`pip install pycairo` (needs nothing else; fonts Inter and DejaVu Serif are already installed). Clone this repo.

## 2. Already done today?
If a topic's `status` contains `<today>` (IST date): if it says `rendered`, just do step 7 for it; if it says
`scheduled`, stop and report that.

## 3. Pick the topics (no repeats)
The topic is the first entry in `maths/topics.json` whose `status` is empty. Never reuse a topic whose status is set.
No repeated content (Suraj, 2026-11-28): before picking, also check `maths/topics/` and `reels/` so no idea,
fact or main visual that was already made comes back under another name. Consecutive days should switch area (e.g.
geometry/visual proof, then numbers/probability/pattern); if the next empty topic is too close to yesterday's,
take the next suitable one instead. Hooks, captions and the wow visual must be new each time.
If fewer than 7 empty topics remain, append 15 new, correct, visual topics to the list (same fields), so the
queue never runs dry. Never add a topic that is already in the list under another name.

## 4. Write the topic module `maths/topics/<slug>.py`
**ONE fixed template for every maths reel (Suraj, 2026-11-28): same layout, same style, only the topic and its
animation change.** The template is locked in `maths/template.py` (background + grid, handle, TAG line, caption
font/position, wow flash, "YOUR TURN" question end card, progress bar, fade, music + export). Never change
`template.py`, `engine.py` styling, `sound.py` or `make.py` for a topic, and never draw your own background,
handle, captions, flash, end card or fade. `engine.render` runs `template.check()` and refuses a topic that
breaks the contract.

Copy the shape of `maths/topics/odd_squares.py` (the reference template topic). The module defines `TAG`,
`TITLE`, `DURATION` (35-55 s), `WOW_AT`, `MUSIC_SEED` (= topic n mod 3), `QUESTION_AT`, `QUESTION` (<= 40 chars),
`CAPTIONS` [(text <= 48 chars, t0, t1)], optional `camera(r, t)`, `scene(r, t)` (visuals only), `sfx()`,
`YT_TITLE`, `CAPTION`, `HASHTAGS`, and a docstring listing every number it shows, each checked.
Use the helpers in `maths/engine.py` (`math_row`, `text`, `rect`, `circle`, `line`, `glow`, camera via
`set_camera` + `push_world`/`pop`, easing `prog`/`ease`/`ease_back`/`window`) and the engine palette only
(ORANGE, CYAN, PINK, YELLOW, GREEN, VIOLET, WHITE, DIM).

Story (always): **hook** in the first 1-3 s (frame 0 must already show the hook: it is the thumbnail) ->
**visual exploration** (shapes/graphs moving, not text) -> **step-by-step explanation** (equation morphs,
colour-coded to the shapes) -> **wow moment** at `WOW_AT` (riser ending there + boom + flash + particles) ->
**ending** with the general formula (drawn by `scene` above y 1000) and the template end card from `QUESTION_AT`.

Rules:
- Every number, formula and graph must be correct. Compute values in Python, never type them from memory.
  If a fact cannot be verified, change the topic angle rather than guess.
- Keep scene content between y = 260 and y = 1440 (safe area; the template owns y < 250 and the caption band).
- Sound: a `click` or `pop` when a number or shape appears (rising `pitch` for sequences), `whoosh` on scene
  changes, `chime` when a result lands, `riser` + `boom` + `sparkle` at the wow. Gains 0.4-0.9.
- Make every animation explain something; no random motion.

## 5. Check, then render
`python3 -m maths.make <slug> /tmp/p --preview 0,2,<one time per scene>,<WOW_AT+0.5>,<DURATION-1>`
and look at every PNG. Fix overflow, overlap, wrong numbers, empty frames. Then:
`python3 -m maths.make <slug> reels/maths_NNN.mp4` (NNN = topic n, 3 digits; about 2-3 min).
Check `ffprobe`: 1080x1920, 30 fps, h264 + aac, duration = DURATION, size < 15 MB.

## 6. Publish the files
Commit `maths/topics/<slug>.py` + `reels/maths_NNN.mp4` and `status: "rendered <today> 21:00"` in `topics.json`
in one commit, push to `main`.
URL: `https://raw.githubusercontent.com/srjs97/srj-edu-reels/main/reels/maths_NNN.mp4`;
`curl -sI` must give 200 and content-length > 1,000,000 (retry for up to 2 min after the push).
